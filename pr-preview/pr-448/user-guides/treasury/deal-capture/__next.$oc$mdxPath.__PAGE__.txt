# Deal Capture Guide

> **Goal**: Capture a treasury deal (FX Forward, FX Spot, Term Deposit, etc.) and confirm it, which triggers the Event Engine to generate cashflows, journal entries, and risk profiles.
>
> **Prerequisites**: Phase 1 complete (Company active, instruments activated, accounting infrastructure in place).

---

## Step 3.1 — Capture a Deal

**App**: Deals
**Action**: Create, fill fields, save

This is the core treasury transaction. The deal captures all the terms of the trade.

### Header tab
| Field | Value | Notes |
|-------|-------|-------|
| Company | `4ward4u (Pty) Ltd` | Your company |
| Counterparty | *(select counterparty BP)* | Must have active relationship |
| Instrument | `FX Forward` | Must be activated for company |
| Trade Date | *(today's date)* | When the deal was captured |
| Maturity Date | *(future date, e.g. 90 days)* | When the deal matures |
| Acting Capacity | `Own Book` | Own book or On Behalf |
| Dealing Capacity | `Direct` | Direct or Broker |
| Business Rationale | `Hedging USD exposure` | Why this deal was entered |

### Deal Legs tab
| Field | Value | Notes |
|-------|-------|-------|
| Leg 1 Direction | `Pay` | Pay leg |
| Leg 1 Notional | `100000.00` | Amount |
| Leg 1 Currency | `ZAR` | Pay currency |
| Leg 1 Value Date | *(maturity date)* | When leg settles |
| Leg 2 Direction | `Receive` | Receive leg |
| Leg 2 Notional | `5405.41` | Equivalent amount |
| Leg 2 Currency | `USD` | Receive currency |
| Leg 2 Value Date | *(maturity date)* | When leg settles |

### FX Details tab (for FX instruments)
| Field | Value | Notes |
|-------|-------|-------|
| Spot Rate | `18.5000` | Current spot rate |
| Forward Points | `0.0250` | Forward premium/discount |
| All-In Rate | `18.5250` | Spot + forward points |
| Currency Pair | `ZAR/USD` | Base/Quote |
| Tenor | `3M` | 3 months |

**After saving**: Note the Deal UUID. Status is `CAPTURED`.

---

## Step 3.2 — Confirm the Deal

**App**: Deals
**Action**: Click "Confirm Deal"

This is the critical step that triggers the Event Engine pipeline.

1. Open the Deal record
2. Click "Confirm Deal"
3. SoD check runs (capturer cannot be confirmer)
4. Status changes from `CAPTURED` to `CONFIRMED`
5. Event Engine fires automatically

**What happens after confirmation**:
- ENG_CASH: Generates projected Cashflow Items
- ENG_RISK: Creates Risk Profile
- ENG_LMT: Checks/reserves Limits
- ENG_COMPL: Runs Compliance checks
- ENG_ACC: Generates Journal Entries
- ENG_BUD: Budget attribution
- ENG_ROUND: Rounding and hash chain
- ENG_NOTIF: Notifications

---

## Step 3.3 — View Generated Cashflow Items

**App**: Deals (Cashflow Items section)
**Action**: View the Cashflow Items tab on the confirmed deal

After confirmation, cashflow items are automatically generated.

| Field | Description |
|-------|-------------|
| Cashflow Reference | Unique reference for each cashflow |
| Cashflow Type | `Principal`, `Interest`, `Settlement` |
| Cashflow Direction | `Inflow` or `Outflow` |
| Amount | Cashflow amount |
| Currency | Cashflow currency |
| Value Date | When the cashflow is due |
| Cashflow Status | `Projected` |

---

## Step 3.4 — View Generated Journal Entries

**App**: Journal Entries
**Action**: View the journal entries created for the deal

The accounting engine generates double-entry journals.

| Field | Description |
|-------|-------------|
| Deal | Link to the confirmed deal |
| Occasion Type | `Deal Confirmed` |
| Postings | Debit and credit entries |
| Status | `Posted` |

Each journal entry has postings that debit and credit the GL accounts configured in Phase 1.

---

## Step 3.5 — View the Deal in Positions

**App**: Positions
**Action**: View the position created for the deal

After confirmation, a position is created that tracks the open exposure.

| Field | Description |
|-------|-------------|
| Position Reference | Links to the deal |
| Status | `Open` |
| Notional | Deal notional amount |
| Currency | Deal currency |
| Maturity Date | When the position matures |

**After Phase 3**: The deal is confirmed and all downstream records (cashflows, journals, positions) are generated. Phase 4 covers the settlement process.
