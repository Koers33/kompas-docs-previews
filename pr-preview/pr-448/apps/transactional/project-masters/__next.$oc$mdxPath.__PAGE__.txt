# Projects Master Data app

Projects Master Data holds, per client, the four lists that project work chooses from: **Payment Groups**, **Project Phase Categories**, **Project Item Types** and **Project Item Categories**. The list shows one row per client — filter by **Client Business Partner** — and opening a client gives you those four sections.

## What is this app for?

The app keeps a client's project vocabulary current. A **Project Item Type** carries a code and a description; the other three lists carry a name; every row also carries an active flag and the client it belongs to.

Those rows are what the rest of the platform offers when someone captures work for that client, so a missing type or category here is a missing choice later.

## When should I use this app?

Use it when a client's project setup changes — a new phase category, a new item type, a new item category, a new payment group — and when you want to check what is on offer before someone captures an item for that client.

Capturing the work itself belongs to the [Project Items app](/apps/transactional/project-items), and the projects and phases it hangs off are maintained in the Projects app.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). No narrower launchpad audience is recorded for it, so it is treated as available to anyone with portal access.

The service behind the screen scopes it by relationship: the **Treasury** role has full use of these records, a **Client**-role user linked to the client business partner as a **Project Manager** gets the same use for that client, and the same link as a **Project Viewer** gets read-only access. A client user therefore sees only the clients they are linked to.

## How does work progress in this app?

1. Find the client in the list and open the record.
2. Add or edit rows in **Payment Groups**, **Project Phase Categories**, **Project Item Types** and **Project Item Categories**.
3. Save. Each row is stamped with the client of the record you added it under, so it can only ever belong to that client.
4. When a choice is no longer wanted, switch its active flag off instead of deleting it — the app offers no delete command for the record or its rows.

## What can change what I see or do?

- **The client is fixed on the record.** It cannot be changed here, and every row you add inherits it, so a row can never be moved between clients.
- **No new client records.** The list holds the clients that already have project master data; a new record cannot be created or deleted in this app.
- **Names and codes are required.** An item type needs both its code and its description, and each of the other lists needs its name.
- **Value helps follow this record.** The item type, item category and payment group choices offered in Project Items are filtered to the client on the item, and the phase choices follow the project chosen for it, so a choice set up for one client is never offered for another.

## Where can I review the results?

Reopen the four sections — what you saved is what they show, with the client on each row. The end-to-end check is in the [Project Items app](/apps/transactional/project-items): open an item for that client and confirm that the lists in its value helps contain what you just maintained.

## What should I check if I can’t continue?

- **A type or category is missing when an item is captured:** check this record for that client, and check the client on the item itself — the value help only offers rows belonging to that client.
- **There is no create command for the client record:** new client master records are not created in this app — note the client and raise it with your platform administrator.
- **There is no delete command:** rows are retired with their active flag instead of being removed.
- **A permission message:** your role or relationship does not cover that client — see [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

No task guide is published for this app yet; adding a row, changing one and checking the result are covered on this page. Read [Using the Fiori Apps](/getting-started/using-fiori-apps) once for how drafts, value helps and save behaviour work across the platform.
