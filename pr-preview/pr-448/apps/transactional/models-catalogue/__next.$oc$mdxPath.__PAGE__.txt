# Models Catalogue app

Models Catalogue is the register of models the platform uses. Each registration records a **Model Code**, a **Model Name**, a **Version**, the **Status** the model has reached, when it was registered and who registered it.

## What is this app for?

The record has two sections. **General Information** holds the registration itself — code, name, version, status, registration date and registrant. **Governance** holds the audit stamps for the record: when and by whom it was created and last changed.

The status list is what gives a registration its meaning:

- **Development** — the model is under development and not yet approved for use.
- **Validated** — the model has passed independent validation.
- **Production** — the model is approved and in production use.
- **Retired** — the model has been retired from use.

## When should I use this app?

Register a model when it is first adopted, add a new version when the model is reissued, and update the status when the model's stage changes. Come here to correct a registration detail such as the name or the registration date, or to check which models are registered and where each one stands.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). Registrations are readable, creatable and updatable for portal access, with no additional role restriction and no narrower launchpad audience recorded, so everyone who can open the app works with the same list.

## How does work progress in this app?

1. Select **Create** to open a new registration in draft. It starts with **Status** set to **Development** and **Registered At** set to today; **Registered By** is filled with you when a user record exists for your sign-in.
2. Enter the **Model Code**, the **Model Name** and the **Version**, then choose the **Status** that describes where the model stands.
3. Save. Correct the record later the same way — the registration date and registrant stay with the record.
4. Move a model through its stages by changing **Status**. The app offers no approval or validation action of its own: the field records the stage, it does not run the work behind it.

## What can change what I see or do?

- **Model Code** is required, must be unique, and cannot be changed after the record exists — a changed code is refused and a second record with the same code is refused as well.
- **Model Name** and **Status** are required, and **Registered At** cannot be in the future.
- Values have fixed lengths: code 50 characters, name 255, version 20. A longer value is refused with a message naming the field and the limit.
- All four statuses are offered at every stage of the record; nothing in the record hides or gates the others.

## Where can I review the results?

The list shows **Model Code**, **Model Name**, **Version**, **Status** and **Registered At** for every registration, so you can see the whole register at a glance. On the record, **General Information** holds the detail you entered and **Governance** shows who created and last changed it and when.

## What should I check if I can't continue?

- A message that the model code already exists: open the existing registration instead of adding a second one.
- A message that the code cannot be changed: the code is fixed once saved; correct the name or version instead.
- A message that a field is required or too long, or that the registration date is in the future: complete or shorten the value and save again. The registered messages are listed in the [22xx error reference](/reference/error-codes/block-22xx-mdl).
- An edit control is missing: check your roles in [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

No task guide is published for this app yet; registering a model, updating a version and changing a status are covered on this page. Read [Using the Fiori Apps](/getting-started/using-fiori-apps) once for how drafts, value helps and save behaviour work across the platform.

## What should I do next?
