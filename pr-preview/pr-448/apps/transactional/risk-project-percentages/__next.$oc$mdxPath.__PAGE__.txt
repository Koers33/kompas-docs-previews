# Risk Project Percentages app

Risk Project Percentages is where the percentage bands held against a business partner are maintained. Each row records a **Business Partner**, a **Minimum Percentage** and a **Maximum Percentage** that define the band, the **Risk Percentage** that goes with it, and whether the row is active.

## What is this app for?

The app holds configuration rather than transactions: a small set of bands per client, put in place by the platform when that client's projects start. Percentages are values between 0 and 100, and the active flag is what keeps a band in use or takes it out of use without removing it.

There are no buttons here — the record itself is the work: the bands, their values and their active state.

## When should I use this app?

Use it to check that a client has its bands in place, to change the risk percentage recorded for a band, to adjust where a band starts or ends, or to retire a band by switching it off.

The platform gives a client its bands automatically: when the first project is created for a client that has no rows yet, the default bands are copied across for that client. That happens in [Projects](/apps/transactional/projects), and the result is what you review here.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). No narrower launchpad audience is recorded for it, so it is treated as available to anyone with portal access.

The records behind the screen are scoped: the rule on this service grants full use of the rows to the **Treasury** role, so users without that role will not be able to read or change them.

## How does work progress in this app?

1. Filter by **Business Partner** and find the client's rows — or wait for the platform to create them when the client's first project is saved.
2. Open a row, adjust the band or the **Risk Percentage**, and save.
3. Switch a band off with the active flag instead of expecting to remove it: there is no delete command for these rows.

There is no approval or status sequence to drive here; a saved row is the finished state.

## What can change what I see or do?

- **The client comes first:** the rows are per business partner, so an empty list usually means that client has not been set up here yet — filter by another client, or check whether a project exists for the one you expect.
- **Percentages must fall between 0 and 100**, including the band boundaries; a value outside that range is refused when you save.
- **Bands are not checked against each other.** Two bands for the same client can overlap or leave a gap, so keep the ranges consistent yourself.
- **The active flag is your working switch:** an inactive row stays on the record and can be switched back on, while a row cannot be deleted from this app.
- **Your role decides whether you see the rows at all** — see [Roles and Access](/getting-started/roles-and-access).

## Where can I review the results?

The list is the check: for the business partner you filtered on, each band shows its minimum, maximum, risk percentage and active state. Reopening a row confirms the values you just saved.

The projects those bands belong to are managed in [Projects](/apps/transactional/projects), where the first project for a client is also what triggers the bands being created.

## What should I check if I can’t continue?

- **A percentage is refused on save:** the value must be between 0 and 100 — correct it and save again.
- **There are no rows for a client:** create or open the client's first project, which copies the default bands, or add the rows yourself.
- **The list is empty or an edit control is missing:** your role does not cover these records — see [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

No task guide is published for this app yet; reviewing and adjusting a client's bands are covered on this page. Read [Using the Fiori Apps](/getting-started/using-fiori-apps) once for how drafts, value helps and save behaviour work across the platform.
