# Button Lists app

Button Lists is a read-only register of the buttons — the platform's named actions — that appear across its apps. Each row shows the button's **Code**, its **Button Name**, the **Button Technical Name** it maps to, the **App** it belongs to, and the **Cost Provision Classification** and **Cost Provision Value** held against it.

## What is this app for?

The register lets you see, in one place, which actions the platform exposes and which app each one belongs to: period close and reopen, deal confirmation and rollover, approvals and rejections, sync and refresh actions, and the informational buttons that open supporting content. The cost-provision fields on each row are the classification and value the platform associates with that action, so the register is the reference point when you are reconciling those settings against the cost provision entries they appear on.

## When should I use this app?

Use Button Lists when you need to check what a button is called or which app owns it, or when you want to verify the cost-provision classification and value held for an action. Use the apps themselves to perform the work — this register describes the buttons rather than running them, and it holds no transactions of its own.

## Who can access this app?

The register applies no role restriction of its own beyond portal access: whether the app appears in your launchpad is a question for your platform administrator (see [Roles and Access](/getting-started/roles-and-access)). Everyone who can open the app sees the same thing: the register is read-only for all users, so nothing is created, changed or deleted here.

## How does work progress in this app?

There is no lifecycle to progress. Open the app, filter the list to the **App** you are investigating, and read the rows. Each row is a reference entry maintained with the platform's configuration data rather than something you maintain yourself.

## What can change what I see or do?

- **The app filter:** narrowing the list to one app is the only thing that changes what you see; clearing it shows the full register again.
- **Read-only everywhere:** the button details and the **Cost Provision Classification** and **Cost Provision Value** fields are not editable, for any user.
- **A row you expect is missing:** rows come from the platform's configuration, so a missing entry cannot be added in this app.

## Where can I review the results?

For any action you can see in an app, find its row here and compare the app it is assigned to. When you are reviewing a cost provision entry, the classification and value on the entry should match the row for the button behind that action; if they differ, the register shows which value the platform holds for the button.

## What should I check if I can't continue?

If a row seems to be missing for an action you can see in an app, note the button and the app and raise it with your platform administrator — this app cannot add entries. If the app itself does not open, check your access first (see [Roles and Access](/getting-started/roles-and-access)).

## Which task guides are available?

No task guide is published for this app yet; it is a reference view rather than a task-based workflow.
