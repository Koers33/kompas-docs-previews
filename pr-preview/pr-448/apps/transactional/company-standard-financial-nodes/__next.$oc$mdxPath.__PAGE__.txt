# Company Standard Financial Nodes app

Company Standard Financial Nodes is where a company claims its own place in the platform's standard financial node structure. Each record maps one **Company Node Code** to a **Global Financial Node** for one company, states which accounting paths that node permits, and records when it takes effect and who approved it. These company nodes are what accounting mapping, treasury accounts and client ledger overlays are built on, so a node is only useful once it is active.

## What is this app for?

A node record answers three questions for one company: which standard node does this company use (**Global Financial Node**), what is it called locally (**Company Node Code**), and what may post through it (**Permitted Paths**, **Effective From**, **Override Mapping**). The **Node Activation** section holds that configuration; the **Approval Record** section holds the outcome of the decision — **Approved By** and the **Approval Record** link.

Activation is the decision the app exists for. An inactive node is a proposal; an active node is one the platform treats as approved for that company.

## When should I use this app?

Use it when a company needs a financial node added or corrected, when an existing node must be switched off, or when you need to confirm that a node is active and who approved it. The node codes themselves are shared across the platform — the global structure is maintained elsewhere in bold **Global Standard Financial Nodes** — while this app is only about one company's use of it. Day-to-day postings are not entered here.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). These records carry no additional role grant of their own, so everyone who can open the app sees the same records and the same **Approve** and **Reject** controls. Records cannot be deleted; switch **Active** off instead. Treat approval as an authorization step and follow your own approval procedure before activating a node.

## How does work progress in this app?

1. Select **Create** to add a node in draft, or open an existing record to correct its configuration.
2. Choose the **Company** and **Global Financial Node**, enter the **Company Node Code**, and set **Permitted Paths**, **Effective From** and **Override Mapping** as needed, then save.
3. With the record saved and not yet active, select **Approve**. Approval switches the record on and stamps **Approved By** with your user, and the platform confirms the node is active and its accounting routing is enabled.
4. To take a node out of use, open an active record and select **Reject**. **Reject** is only offered while the record is active, and it asks for a rejection reason; the reason is required. Rejecting switches the record off and clears the approval details.
5. Approving a node that is already active, or rejecting one that is already inactive, changes nothing: the message tells you the node is already active or already rejected.

Treat this as an orientation to the flow and follow your approval procedure before activating a node.

## What can change what I see or do?

- **Active:** this is the state that decides which action is offered. **Approve** appears only while the record is inactive, **Reject** only while it is active, and the header chip shows **Active** green when on and red when off.
- **The record's own state:** approving a node that is already active, or rejecting one that is already inactive, is refused with a message rather than changing anything.
- **Approval details:** **Approved By** and **Approval Record** are set by the actions, not typed in; they show who activated the node and the approval entry behind it.
- **Value lists:** **Global Financial Node** and **Company** are chosen from fixed lists, so only the nodes and companies your configuration offers are selectable.
- **Deleting:** records cannot be deleted from this app. Reject the node to take it out of use.

## Where can I review the results?

The list shows **Company**, **Company Node Code**, **Global Financial Node**, **Effective From**, **Permitted Paths** and **Active** for every node, so you can see at a glance which nodes a company has and which are live. On the record, **Node Activation** holds the configuration and **Approval Record** holds who approved it and the linked approval entry.

Downstream, the records that consume a node show which one they used: account mappings, treasury accounts and client ledger overlays all point at a company financial node, and the **Preview Posting** action in **Company Instrument Effects** reports the company node it resolves before it reaches an account. Do not assume a record exists for every node — that depends on how far each company's accounting setup has progressed.

## What should I check if I can't continue?

- **Approve** or **Reject** is not offered: the action is gated by **Active** — **Approve** is for inactive records, **Reject** for active ones.
- **Reject** is refused: a rejection reason is required, and the message also tells you if the record is already inactive.
- You are told the node is already active: there is nothing to approve; use **Reject** if the node should come out of use.
- A delete command is refused: node records are retained by design.
- An edit control is missing: check your roles in [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

No task guide is published for this app yet; creating a node, approving it, rejecting it and checking the outcome are covered on this page.
