# Stakeholder Universe app

Stakeholder Universe is the platform's register of roles. Each row is one role — its **Auth Category**, **Role Code** and **Role Name**, a **Description** of what the role does, and the **Screen Access** and **Action Permissions** that record which screens and actions it covers.

## What is this app for?

The register is the answer to "what is this role meant to do?". It groups roles into categories such as treasury, back office, compliance, finance, operations and administration, and for each one records the scope in words plus the screens and actions it is understood to include. The role categories and their plain-language descriptions are published on [Roles and Access](/getting-started/roles-and-access), which is built from this register.

Use it to keep that picture accurate. It is a definition list, not an assignment list: it describes roles, while the people who hold them are managed elsewhere.

## When should I use this app?

Come here when a role's description is wrong or out of date, when a new role has to be defined for the platform, when you need to check what a role is understood to cover before granting it, or when a batch of role definitions has been staged and has to be applied.

Assigning a role to a person is not done here — that is administrator work, and the result is visible in the [User Management app](/apps/transactional/ias-user-management).

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). No narrower launchpad audience is recorded for it. Because these records describe what each role may do, treat edits as consequential and follow your own change procedure before saving them.

## How does work progress in this app?

1. Filter by **Auth Category** to narrow the register to one group of roles.
2. Open a role. **General Information** shows the category, **Role Code**, **Role Name**, **Description**, **Screen Access** and **Action Permissions**.
3. Correct the description or the listed screens and actions, then save. Existing roles can be updated and new ones created; roles are never deleted from this app.
4. Run **Update Entries** when rows have been staged from an import. Staged rows are matched to existing roles on **Role Code** — missing roles are created and existing ones updated — and the action answers with how many it created, how many it updated and any rows it could not apply.

## What can change what I see or do?

- **Auth Category is a fixed set.** The value help offers only the categories the platform has configured, so a role must belong to one of them.
- **Role Code identifies the row.** It is the key staged rows are matched on, so a code that changes breaks the link to staged data.
- **Deletion is not available.** Rows are created and corrected here but never removed, so it is worth getting a **Role Code** right the first time.
- **Import errors come back with the result.** A workbook that is not usable, or a register the import cannot find, is reported rather than silently dropped.

## Where can I review the results?

Reopen the role and check that **Description**, **Screen Access** and **Action Permissions** read as you intended, and that the list shows the corrected **Role Name** beside its **Role Code**. After **Update Entries**, the created and updated counts tell you what landed, and any returned error names the rows that did not.

The wider check is downstream: [Roles and Access](/getting-started/roles-and-access) publishes the categories and what each role is for, and the [User Management app](/apps/transactional/ias-user-management) shows which people currently hold access groups.

## What should I check if I can’t continue?

- **Update Entries reports nothing created or updated:** nothing matching was staged for this register, or the rows were refused — read the error lines it returns.
- **A message about an unusable file or a missing register:** the import could not be applied; the registered messages are listed in the [block 9xx error reference](/reference/error-codes/block-9xx-csh).
- **You can see the register but cannot save:** check your roles in [Roles and Access](/getting-started/roles-and-access) — the records themselves carry no extra restriction beyond portal access.

## Which task guides are available?

No task guide is published for this app yet; looking up a role, correcting one and applying staged rows are covered on this page. Read [Using the Fiori Apps](/getting-started/using-fiori-apps) once for how drafts, value helps and save behaviour work across the platform.

## What should I do next?
