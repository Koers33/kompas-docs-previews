# Global App app

Global App is the platform's single catalogue of global reference data. One **Global App** record carries every shared definition set together — rounding rules and their policy sets and scopes, standard financial nodes, instrument and product catalogues, IRRBB shock scenarios, the hedgeability matrix, payment corridor groupings and countries, change-tracking and data-privacy rules, audit architecture policy, ESG and trade-document templates, legal role requirements, and, under **Markets & Licensing**, the commodity catalogue and instrument licence requirements.

## What is this app for?

This is where the definitions every company inherits are held and reviewed in one place. Company-level configuration — a company's own financial nodes, its accounts, its instruments — is built on these rows, so the app exists to let you see the whole shared set without moving between half a dozen screens.

The object page is a set of tables, one per definition set, and each table is readable on its own.

## When should I use this app?

Use it to review what the platform offers before you configure a company, to check whether a definition exists before you go looking for it downstream, and to apply a bulk change that has already been staged as an import.

It is not the place for company-specific configuration — a company's own use of a financial node belongs in the [Company Standard Financial Nodes app](/apps/transactional/company-standard-financial-nodes), and company records belong in the [Companies app](/apps/transactional/companies).

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). Its own authorization records grant the standard read, create and update operations to holders of portal access, and no narrower launchpad audience is recorded.

## How does work progress in this app?

1. Open the single **Global App** record — the list holds one row, so there is nothing to filter.
2. Read the section you need. Each facet is a table of the definitions in that set.
3. If you are loading a bulk change, the rows are staged against the target catalogue first rather than written straight through.
4. Run **Push** from the object page header. Push applies the rows staged for the catalogue you name and answers with a count of created and updated rows.
5. Reopen the section table to confirm the rows are now present.

## What can change what I see or do?

- **One record only:** the root row is a singleton and is created by the platform, so you always open the same record.
- **Nothing is deleted from here:** every section is marked non-deletable, so a row that is wrong is corrected rather than removed.
- **Push needs a known target:** if the platform does not recognise the catalogue you name, or no staging catalogue exists for it, nothing is applied and the message tells you which of the two happened.
- **Push updates rather than duplicates:** a staged row that already matches an existing record updates it, and the identifying code of a row — a node code, instrument code or family code, for example — is never overwritten. Only the other columns change.
- **Import results:** a push answers with how many rows were created and how many updated, alongside any rows it could not apply.

## Where can I review the results?

The section tables themselves are the check: each shows the code, name and the columns that matter for that definition set, and they update once a push has run. Rows staged for a push are held against the catalogue entry and can be read in the **Master Data Catalogue** before you apply them.

The same definitions also appear in their own maintenance apps — standard financial nodes, for example, are maintained in the [Global Standard Financial Nodes app](/apps/transactional/global-standard-financial-nodes), where the full record including its description and active flag is editable.

## What should I check if I can’t continue?

- A message that an entity name is required, or that the value is not recognised: the action was started without a valid target — run it again against one of the definition sets on this page.
- A message that the staging catalogue was not found: nothing has been staged for that set yet, so there is nothing to push.
- A message that the push or refresh failed: nothing was applied; check which rows the message names and retry once they are corrected.
- The registered messages for this app are listed in the [block 1xx error reference](/reference/error-codes/block-1xx-glb).

## Which task guides are available?

No task guide is published for this app yet; reviewing a definition set, applying a staged push and checking the outcome are covered on this page. Read [Using the Fiori Apps](/getting-started/using-fiori-apps) once for how drafts, value helps and save behaviour work across the platform.
