# Business Partners Testing Guide

This guide walks you through testing the **Business Partners** app on the live BTP
Cloud Foundry deployment, covering:

1. Creating an Organization Business Partner with all sub-records
2. Creating Natural Person BPs for contact people
3. Linking Business Partners with relationships and testing authorization

---

## FLOW 1 — Create an Organization Business Partner

**App**: Business Partners (Work Zone tile)  
**Role needed**: Treasury  
**Under test**: Create org BP, populate addresses/banks/emails/phones, set client flags, KYC/AML, SSI

### Step 1.1 — Open the Business Partners App

From the Work Zone launchpad, click the **Business Partners** tile. You will see a
**List Report** with a searchable table of all business partners.

### Step 1.2 — Click Create

Click the **Create** button in the toolbar. A new draft Business Partner opens on the
Object Page.

### Step 1.3 — Fill in the Identification Section

| Field                        | Value                                    | Notes                                      |
|------------------------------|------------------------------------------|--------------------------------------------|
| **Party Type**               | Select from value help                   | Classifies the party type                  |
| **Business Partner Category**| **Organization** (code `01`)             | REQUIRED. Use value help. This is the category for company/org BPs |
| **Organization Name**        | `ACME Corporation (Pty) Ltd`             | Display name for the organization          |
| **Legal Name**               | `ACME Corporation Proprietary Limited`   | Full registered legal name                 |
| **Short Code**               | `ACME`                                   | Exactly 4 chars, format `[A-Z0-9]{4}`. Must be unique |
| **Legal Entity Identifier**  | `5493001AB2CD3EF4GH56`                   | 20-character LEI code (use a valid-format test LEI) |

### Step 1.4 — Set Client Flags

Scroll to the client-related fields:

| Field                        | Value      | Notes                                           |
|------------------------------|------------|--------------------------------------------------|
| **Is Client**                | `true`     | Check the box — this marks the BP as a client    |
| **Is Approved for Trading**  | `true`     | Defaults to true, leave as-is                    |
| **Is Fiduciary**             | `false`    | Only enable if the org acts as a fiduciary       |
| **Client Code**              | `CLI-001`  | Internal client reference                        |
| **Client Type**              | Select from value help | References ClientTypes master data      |
| **Client Status**            | Select from value help | References ClientStatuses master data   |
| **Counterparty Code**        | `CP-001`   | Counterparty reference                           |

## FLOW 3 — Link Business Partners with Relationships

**App**: Business Partners  
**Role needed**: Treasury  
**Under test**: Business Partner Relationships (parent/child linking) and authorization cascade

### Understanding the Relationship Model

```
Organization BP (parent)
  └── to_BusinessPartnerChildren
       ├── John Smith   → relationshipType: CEO (15)
       ├── Jane Doe     → relationshipType: CFO (16)
       ├── Bob Trader   → relationshipType: Trader (02)
       └── Carol Admin  → relationshipType: Client Admin (19)

Natural Person BP (child)
  └── to_BusinessPartnerParents
       └── ACME Corporation  → relationshipType: CEO (15)
```

The relationship is **bi-directional**: viewable from both the parent's Children table
and the child's Parents table.

### Key Relationship Types and Their Authorization Effects

| Code | Area | Name               | Authorization Impact on the Child                    |
|------|------|--------------------|------------------------------------------------------|
| 19   | SF   | **Client Admin**   | Can **UPDATE** the parent Organization BP            |
| 27   | SF   | **Partner Manager**| Can **READ** the parent Organization BP              |
| 29   | TD   | **Deals Manager**  | Can CREATE, READ, UPDATE deals for the org           |
| 30   | TD   | **Deals Viewer**   | Can READ deals for the org                           |
| 28   | TD   | **On Behalf Of**   | Can trade on behalf of the org                       |
| 02   | SF   | Trader             | Role designation — used in deal workflows            |
| 03   | SF   | Approver           | Role designation — used in approval workflows        |
| 01   | LG   | Contact            | Informational — no special authorization             |
| 07   | LG   | Compliance Officer | Role designation                                     |
| 15   | LG   | CEO                | Role designation                                     |
| 16   | LG   | CFO                | Role designation                                     |
| 14   | LG   | Share Holder       | Informational — use `ownershipPercentage` field      |

## BTP Troubleshooting

| Issue                                              | What to Check                                                                                  |
|----------------------------------------------------|------------------------------------------------------------------------------------------------|
| IAS User Management shows no users                 | `cua-ias` destination configured in BTP Destination Service? IAS trust established? Check `cf logs kompas-srv --recent` for SCIM API errors |
| Refresh Data fails with error                      | IAS SCIM API credentials in `cua-ias` destination may be expired. Check destination configuration |
| Claim User says "BusinessPartner already exists"   | User was previously claimed. Check `hasPartner` flag — if true, the BP already exists |
| Onboard Client fails                               | IAS group "Kompas Client" must exist in the IAS tenant. Check `cf logs kompas-srv --recent` |
| Revoke Access does not immediately block user      | XSUAA tokens are cached (typically 30 min). User retains access until token expiry |
| Client user cannot see organization BP             | Relationship must be `isActive = true`, `child_ID` must match the user's IAS user ID (which equals their BP ID), and the user must have the Client role |
| Client Admin cannot edit organization BP           | Relationship type must be `19` (Client Admin). Types `27` (Partner Manager) or `01` (Contact) only grant READ, not UPDATE |
| Cannot save BusinessPartner                        | `shortCode` must be exactly 4 chars matching `[A-Z0-9]{4}`. Check all mandatory fields are filled |
| Organization name field missing                    | Ensure `businessPartnerCategory_code = "01"` (Organization — code 01 in this system). If Natural Person (02), the org name field won't appear |
| Sub-tables (Addresses, Banks, etc.) don't save     | Each composition must be added via the **+** button in its own table toolbar, not on the main form |
| 403 Forbidden on any action                        | Your user does not have the required XSUAA role. Check role collection assignments in BTP cockpit → Security → Role Collections |
| 500 Internal Server Error                          | Check backend logs: `cf logs kompas-srv --recent`. Likely PostgreSQL constraint violation or IAS API failure |
