# Business Partners for Treasury

> **Last updated: 2026-08-19**
>
> **This guide is subject to change and is provided for feedback purposes.** The sections, fields, and behaviours described here are based on the current system implementation and may be updated as the platform evolves. Please share any feedback or corrections with the Development team.

> **This guide is written for users logged in with the Treasury role.** As a Treasury user, you have full access to all Business Partners in the system. You can create, read, and update any Business Partner record and add data to all sections — including sections that are hidden from Client users.

---

## Your Access Level

Treasury users have unrestricted access to the Business Partners app. Unlike [Client users](../admin/client-onboarding.md), you can:

- **View** any Business Partner (Organization, Person, or Group)
- **Edit** any Business Partner's core fields (name, category, status, codes)
- **Create** new Business Partners of any category
- **Add and edit** entries in all sections on any Business Partner's Object Page

---

## How to Navigate Business Partners

1. Log in to SAP Build Work Zone.
2. Open the **Business Partners** app from the launchpad.
3. The List Report shows all Business Partners. Use the table views to filter by category:
   - **Organizations** — companies, banks, counterparties
   - **Persons** — natural persons (users, contacts, directors)
4. Click on any row to open its Object Page.

---

## Sections Available on Organization Business Partners

When you open an Organization Object Page, you have access to all sections:

| Section                    | What It Contains                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------- |
| **Organization**           | Organization Name, Legal Name, Short Code, Business Partner Category, Allow Internal Contracts |
| **Client & Trading Setup** | Client Code, Client Type, Client Status, Fiduciary flag, Trading approval, margins, bank costs |
| **Addresses**              | Physical addresses with province, postal code, country                                         |
| **Company Emails**         | Company email addresses by type                                                                |
| **Company Phone Numbers**  | Company phone numbers by type                                                                  |
| **Bank Accounts**          | Bank details for settlements (currency, SWIFT, IBAN, account number)                           |
| **Children**               | Relationships where this BP is the parent                                                      |
| **Parents**                | Relationships where this BP is the child                                                       |
| **Documents**              | File attachments (registration certificates, IDs, proofs)                                      |
| **Compliance**             | Know Your Customer and Anti-Money Laundering screening records                                 |
| **Mandates**               | Mandate types with instrument scope and authority limits                                       |
| **SSIs**                   | Standard Settlement Instructions by currency (bank identifier, account)                        |
| **Licences**               | Regulatory licences with type, number, issuing authority, expiry                               |
| **Ratings**                | Credit ratings from agencies                                                                   |
| **Notes**                  | General notes                                                                                  |
| **Change History**         | Audit trail of changes made to the record                                                      |

---

## Sections Available on Person Business Partners

When you open a Person Object Page, the available sections are:

| Section            | What It Contains                               |
| ------------------ | ---------------------------------------------- |
| **Natural Person** | First Name, Middle Name, Last Name, Birth Date |
| **Addresses**      | Physical addresses                             |
| **Emails**         | Email addresses                                |
| **Phone Numbers**  | Phone numbers                                  |
| **Children**       | Relationships where this BP is the parent      |
| **Parents**        | Relationships where this BP is the child       |
| **Documents**      | File attachments                               |
| **Qualifications** | Professional qualifications and certifications |
| **Notes**          | General notes                                  |
| **Change History** | Audit trail of changes made to the record      |

---

## Creating a New Business Partner

1. Click **Create** in the List Report.
2. Select the **Business Partner Category**:
   - `01` — Organization
   - `02` — Natural Person
   - `03` — Group
3. Fill in the required fields (see below).
4. Click **Save** (or **Activate** if draft-enabled).

### Required Fields by Category

**Organization:**

| Field                         | Notes                     |
| ----------------------------- | ------------------------- |
| **Business Partner Category** | Select `Organization`     |
| **Organization Name**         | The legal or trading name |

**Person:**

| Field                         | Notes                   |
| ----------------------------- | ----------------------- |
| **Business Partner Category** | Select `Natural Person` |
| **First Name**                | Person's first name     |
| **Last Name**                 | Person's last name      |

### Optional Fields (Organization)

| Field                        | Notes                                   |
| ---------------------------- | --------------------------------------- |
| **Legal Name**               | Full registered name                    |
| **Short Code**               | 4-character uppercase alphanumeric code |
| **Allow Internal Contracts** | Enable internal contracts for this BP   |
| **Client Code**              | Assigned client identifier              |
| **Client Type**              | Type of client relationship             |
| **Client Status**            | Current client status                   |
| **Counterparty Code**        | Assigned counterparty identifier        |
| **Counterparty Status**      | Current counterparty status             |
| **Legal Entity Identifier**  | LEI code                                |
| **Jurisdiction**             | Legal jurisdiction                      |

---

## Managing Relationships (Children / Parents)

Relationships between Business Partners control access for Client users and determine which counterparties appear in transactional services.

### Common Relationship Types

| Relationship Type   | Code | Area                  | Purpose                                                       |
| ------------------- | ---- | --------------------- | ------------------------------------------------------------- |
| **Client Admin**    | `19` | SF (System Functions) | Grants the child BP full admin access to the parent's profile |
| **Partner Manager** | `27` | SF (System Functions) | Grants the child BP management access to the parent's profile |
| **Project Manager** | `20` | SF (System Functions) | Grants the child BP full access to the parent's Projects      |
| **Project Viewer**  | `21` | SF (System Functions) | Grants the child BP read-only access to the parent's Projects |
| **Request Author**  | `22` | SF (System Functions) | Grants the child BP full access to the parent's Requests      |
| **Request Viewer**  | `23` | SF (System Functions) | Grants the child BP read-only access to the parent's Requests |
| **Deals Manager**   | `29` | TD (Trading)          | Grants the child BP deal management access                    |
| **Deals Viewer**    | `30` | TD (Trading)          | Grants the child BP read-only deal access                     |
| **Bank**            | `06` | CL (Clients)          | Makes the child BP appear as a counterparty (banking)         |
| **FSP Trader**      | `09` | TD (Trading)          | Makes the child BP appear as a counterparty (FSP)             |
| **Supplier**        | `11` | CL (Clients)          | Makes the child BP appear as a counterparty (supplier)        |
| **Customer**        | `26` | TD (Trading)          | Makes the child BP appear as a counterparty (customer)        |

### Creating a Relationship

1. Open the parent Business Partner's Object Page.
2. Scroll to the **Children** section.
3. Click **Create**.
4. Fill in:

| Field                 | Notes                                               |
| --------------------- | --------------------------------------------------- |
| **Child**             | Select the child Business Partner from the dropdown |
| **Relationship Type** | Select the appropriate type                         |
| **Area**              | Select the area (auto-suggested based on type)      |
| **Active**            | Defaults to `true`                                  |

5. Click **Save**.

## Test Cases

### Test Case 1: Enabling Client Access on a Business Partner

**Precondition:** You have an Organization Business Partner (e.g., 4ward4u) that is not yet marked as a Client.

**Purpose:** Certain sections on the Object Page are hidden until the Business Partner is granted Client access (`isClient = true`). This test case demonstrates which sections appear and what they contain.

**Steps:**

1. Open the **Business Partners** app.
2. Open the Organization's Object Page (e.g., 4ward4u).
3. Scroll to the **Client & Trading Setup** section (this section is only visible for Organizations).
4. In the **Client Profile** sub-section, set:

| Field             | Value                | Notes                               |
| ----------------- | -------------------- | ----------------------------------- |
| **Is Client**     | `true`               | Grants Client access to this BP     |
| **Client Code**   | `4W4U`               | Unique client identifier            |
| **Client Type**   | Select from dropdown | Type of client relationship         |
| **Client Status** | Select from dropdown | Current client status               |
| **Is Fiduciary**  | `false`              | Check if this is a fiduciary client |

5. In the **Trade Configuration** sub-section, set:

| Field                                | Value       | Notes                                       |
| ------------------------------------ | ----------- | ------------------------------------------- |
| **Is Approved for Trading**          | `true`      | Allows this client to participate in trades |
| **Allow Internal Contracts**         | `true`      | Enables internal contracts for this client  |
| **Internal Contract Margin on Rate** | Enter value | Margin applied to internal contracts        |
| **Separate Bank Costs**              | `false`     | Whether bank costs are billed separately    |
| **Client Bank Cost Amount**          | Enter value | Fixed bank cost amount                      |
| **Client Add Cost Rate**             | Enter value | Additional cost rate                        |

6. Click **Save**.

**What changes after enabling Client access:**

Once `isClient` is set to `true`, the following sections appear on the Object Page (they were previously hidden):

| Section                              | What It Contains                                                           |
| ------------------------------------ | -------------------------------------------------------------------------- |
| **Compliance (KYC / AML)**           | Know Your Customer and Anti-Money Laundering screening records             |
| **Mandates**                         | Mandate types with instrument scope and authority limits                   |
| **Standard Settlement Instructions** | SSI details by currency (bank identifier, account)                         |
| **Client & Trading Setup**           | Client profile and trade configuration (already visible for Organizations) |

These sections allow Treasury to configure the full client trading setup, compliance requirements, and settlement instructions.

**What Client users see vs Treasury:**

When a Client user logs in, they **cannot** see the following fields that Treasury can see:

| Field                                | Hidden from Clients |
| ------------------------------------ | ------------------- |
| **Is Client**                        | Hidden              |
| **Is Approved for Trading**          | Hidden              |
| **Allow Internal Contracts**         | Hidden              |
| **Internal Contract Margin on Rate** | Hidden              |
| **Separate Bank Costs**              | Hidden              |
| **Client Bank Cost Amount**          | Hidden              |
| **Client Add Cost Rate**             | Hidden              |

These fields are only visible to Treasury users, ensuring that client configuration is managed centrally and not editable by the Client user themselves.

**Expected result:** The Organization now has the full set of client-related sections visible. Treasury can configure compliance records, mandates, settlement instructions, and trading parameters. The Client user of this Organization (if they have a child-parent relationship) will see the sections but cannot edit the trading configuration fields.
