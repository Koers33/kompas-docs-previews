# Project Items app

Project Items is the working list of the items that make up a client project — the work, purchases and forex steps tracked against a project and its phases. Every row carries an auto-assigned **Reference Number** and its **Item Status**, shown as a coloured icon in the list, alongside the **Client**, **Counter Business Partner**, **Project** and **Project Phase** it belongs to.

## What is this app for?

An item is the unit of work you track and take forward. **General Information** holds the item's type, category, description, amount, symbol and transaction side, payment group, country, dates and **Confidence Percentage**; **Notes** holds the discussion around it and **Documents** holds its files.

The **Reference Number** is generated for you when the record is created, so you can quote it in emails and requests without numbering anything yourself.

## When should I use this app?

Use it to capture an item for a project, to follow one to its **Item Target Date**, and to take a finished item forward into a client request or a payment request.

The project and its phases are maintained in the Projects app, and the client-specific choices this app offers — item types, item categories, payment groups — are maintained in the [Projects Master Data app](/apps/transactional/project-masters).

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). No narrower launchpad audience is recorded for it, so it is treated as available to anyone with portal access.

The service behind the screen scopes what each user sees: the **Treasury** role has full use of these records, including creating requests and payment requests and duplicating an item. A user holding the **Client** role gets the same use only for a client business partner they are linked to as a **Project Manager**, and only read-only access when that link is a **Project Viewer**. Client users therefore see a narrower set of items than treasury users do.

## How does work progress in this app?

1. Create an item: choose the client, then the project, which brings the phase, item type, item category, payment group and counter business partner choices for that client. Add the target date, amount, confidence and any forex details, then save — the **Reference Number** is assigned on creation.
2. Work the item in **General Information**, recording discussion in **Notes** and files in **Documents**.
3. From the header of a saved item, take it forward:
   - **Create Request** — choose the request type in the dialog. The platform opens a new request draft carrying the item's client, project, amount, currency pair and side, and takes you to it.
   - **Create Payment Request** — choose the payment option. A payment request draft is opened for the item and the item's **Item Status** becomes **In For Payment**.
   - **Duplicate Project Item** — starts an unsaved copy of the item for you to adjust.
   - **Open Project** — jumps to the project the item belongs to.
4. The status on the item, and in the list, is the check that the step landed.

## What can change what I see or do?

- **The item must be saved first.** **Create Request**, **Create Payment Request** and **Duplicate Project Item** are offered only once the record is active; an unsaved item or an unsaved duplicate shows none of them.
- **The client and project drive the value helps.** Changing them refreshes the counter business partner, project and phase, and the phase, item type, item category and payment group lists are filtered to the client and project you chose — an option that belongs to another client is never offered.
- **Payment requests are for buy-side items.** **Create Payment Request** produces a payment request only when the item's **Transaction Side** is **Buy**; otherwise nothing is created and the message tells you required information is still pending.
- **Forex dates must be trading days.** **Forex Required Date** appears only when **Need Forex** is ticked, and a date that falls on a weekend or a registered non-trading date is refused when you save.
- **Some fields are fixed.** The project cannot be changed once the item exists, and the phase, item type, item category, counter business partner, target date, client and confidence are required before the record will save.
- **Role scope changes the list.** A client user linked as a **Project Viewer** sees the item read-only, with none of the creation actions.

## Where can I review the results?

Start with the list: the **Reference Number** and **Item Status** tell you where each item stands. The **Notes** and **Documents** sections on the same object page hold the evidence for the item.

A request or payment request you raised appears in the Requests app or the [Payment Requests app](/apps/transactional/payment-requests) as a draft to continue there, and the cost entries the platform raises for these actions are recorded in the [Cost Provisions app](/apps/transactional/cost-provisions).

## What should I check if I can’t continue?

- **The forex date is refused:** pick a trading day — weekends and dates listed in the [Non Trading Dates app](/apps/transactional/non-trading-dates) are not accepted.
- **No creation actions appear:** the item is not saved yet, or your role only covers reading it — see [Roles and Access](/getting-started/roles-and-access).
- **A payment request is not created:** check that the item's **Transaction Side** is **Buy**; the message on screen says required information is still pending.
- **The save is refused:** a mandatory value is missing — the message names the field, which is one of the project, phase, item type, category, counter business partner, target date, client or confidence.
- **An option is missing from a value help:** it belongs to another client or project, or it has not been set up yet — see the [Projects Master Data app](/apps/transactional/project-masters).

## Which task guides are available?

No task guide is published for this app yet; capturing an item, raising a request or payment request and duplicating an item are covered on this page. Read [Using the Fiori Apps](/getting-started/using-fiori-apps) once for how drafts, value helps and save behaviour work across the platform.

## What should I do next?
