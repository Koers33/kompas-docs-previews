# Payment Remainders app

Payment Remainders is the master-data list behind the **Payment Remainder** choice that other records offer — most obviously a payment request. Each entry is a **Code** with a **Name**, a **Description** and an **is Active** flag, and the entries supplied are **To CFC**, **Sell For Own Currency** and **Keep Remainder IC**.

## What is this app for?

An entry is a configured option, not a transaction. It exists so that a record offering a **Payment Remainder** choice presents a fixed, consistent set of answers instead of free text. The app is where you maintain those options: correct a description, add a new option, or mark an option that is no longer in use.

## When should I use this app?

Use it when the **Payment Remainder** choices on another record need maintaining, or when you want to confirm what a chosen value is called before you act on the request that carries it. Day-to-day payment work belongs in the [Payment Requests app](/apps/transactional/payment-requests) and the [Payment Instructions app](/apps/transactional/payment-instructions) — this app only holds the menu those records choose from.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). These entries carry no additional role grant of their own, so everyone who can open the app sees the same list and the same editing controls.

## How does work progress in this app?

1. Select **Create** to add an entry, or open an existing one to correct it. The record opens as a draft until you save it.
2. Give the entry a **Code** and a **Name** — the code is what the option is keyed on — then add a **Description** and set **is Active**.
3. Save. There is no approval step: the entry is available to other records as soon as it is saved.

## What can change what I see or do?

- **Choices come straight from this list:** if a **Payment Remainder** option you expect is missing on a payment request, it has not been added here yet.
- **Codes are the identity of an entry:** records store the code they were saved with, so add a new entry rather than repurposing one that is already in use.
- **Deleting is refused by design:** entries are retained, so the **is Active** flag is how an entry is marked out of use.
- The value help on the consuming record is a fixed list, so there is no free-text fallback if an option is absent.

## Where can I review the results?

The list itself is the check: it shows **Code**, **Name**, **Description** and **is Active** for every entry, which is enough to confirm what is configured without opening anything. The effect is visible on the record that uses the choice — open a payment request and read its **Payment Remainder** field in the **General** section to see which option was selected.

## What should I check if I can't continue?

- A delete command is refused: entries are kept by design.
- A choice is not offered on another record: add it here first, then reopen the other record.
- An edit control is missing: check your roles in [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

- [Maintain payment remainder options](./maintain-payment-remainder-options)

## What should I do next?
