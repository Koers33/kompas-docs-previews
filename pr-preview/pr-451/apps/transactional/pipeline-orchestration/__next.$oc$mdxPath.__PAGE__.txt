# Pipeline Orchestration app

Pipeline Orchestration is the read-only record of the platform's effect executions — one row per run of the processing pipeline for a deal event. Each execution carries its **Execution Status**, **Started At** and **Completed At**, a **Scenario Mode** flag and a **Correlation ID** that ties related records together.

## What is this app for?

When the platform processes a lifecycle event on a deal, it opens an execution record so the run leaves a trace: when it started, when it finished and, when it went wrong, which step it stopped at. The app is the place to answer "did that event process, and if not, why?".

Each run works through a fixed sequence of domains — economics, funds transfer pricing, cashflow projection, risk, accounting, compliance, budget, notification and evidence capture — running the ones switched on for that company, instrument and event, and skipping the rest. When everything completes the status becomes `COMPLETED`; if a domain fails, the steps already completed are reversed and the run ends `ROLLED_BACK`, or `FAILED` when that reversal itself does not succeed. When the platform recognises a repeat of work it has already done, the run is marked `IDEMPOTENT` and the original outcome is returned instead of processing twice.

Nothing here is entered by hand: create, edit and delete are switched off for every record, and the app offers no action buttons. It is a monitoring view, not a control panel.

## When should I use this app?

Use it to confirm that a deal event was processed, to find which step a run stopped at, and to tell a scenario run apart from live processing by its **Scenario Mode** flag. Configuration questions — why a domain ran, or why it was skipped — are answered in the [Company Instrument Effects app](/apps/transactional/company-instrument-effects), which holds the matrix that decides the sequence for each event.

Day-to-day deal work stays in the [Deals app](/apps/transactional/deals).

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). Execution records carry no additional role grant of their own, so everyone who can open the app sees the same rows, and no role can turn it into an editing screen.

## How does work progress in this app?

There is nothing to progress in the app itself. An execution appears when the platform runs processing for a deal event, it moves from `INITIATED` to its final status, and you read the result. Any follow-up — changing what runs, reprocessing a deal — happens in the app that owns that work.

1. Filter the list by **Execution Status**, **Started At**, **Completed At** or **Scenario Mode** to find the run you are interested in.
2. Open it and read **Details**: the status, the start and completion times, the **Correlation ID** and, for a run that did not finish, the failure details.
3. Take the failure details, with the **Correlation ID**, to whoever owns the configuration or the deal involved.

## What can change what I see or do?

- **Read-only everywhere:** an empty action toolbar is normal here, not a permissions problem.
- **Status is the story:** `INITIATED` means the run was opened, `COMPLETED` means every enabled domain finished, `ROLLED_BACK` means a failure was reversed, `FAILED` means the run stopped and the reversal did not complete, and `IDEMPOTENT` means the platform recognised a repeat of work it had already done and returned the original outcome instead of processing twice.
- **Failure details are populated only for runs that failed:** **Failure Category**, **Failure Step** and **Failure Code** say which step broke and why — common categories point at the matrix configuration, an expired or blocked matrix row, or an engine failure.
- **Which domains ran is not decided here:** the matrix for the company, instrument, event and acting capacity decides that, and Economics and Evidence Capture always run.
- **An empty list means no processing has run yet** for the filters you have applied — executions cannot be added by hand in this app.

## Where can I review the results?

The list shows status, start and completion time, **Scenario Mode** and **Correlation ID** for every run, so one scan answers whether processing completed. **Details** on the record gives the same information plus the failure fields, which is what to quote when reporting a problem. The deal a run belongs to is not displayed in this app, so keep the **Correlation ID** as the reference when you raise a run with a colleague.

The effects of a successful run are visible in the apps that own them: accounting in the [Journal Entries app](/apps/transactional/journal-entries), cash in the [Cash Account Balances app](/apps/transactional/cash-account-balances), and captured evidence in the [Evidence app](/apps/transactional/evidence). Not every execution produces every kind of record — that depends on which domains ran for it.

## What should I check if I can't continue?

- **A run shows `ROLLED_BACK` or `FAILED`:** read **Failure Category**, **Failure Step** and **Failure Code** and pass them on with the **Correlation ID**; registered messages are listed in the [5xx error reference](/reference/error-codes/block-5xx-res).
- **A domain you expected did not run:** check the matrix row for that company, instrument, event and acting capacity in the [Company Instrument Effects app](/apps/transactional/company-instrument-effects) — a missing, expired or hard-blocked row stops the run.
- **You want to reprocess something:** this app cannot do it; raise it with whoever owns the deal or the configuration.
