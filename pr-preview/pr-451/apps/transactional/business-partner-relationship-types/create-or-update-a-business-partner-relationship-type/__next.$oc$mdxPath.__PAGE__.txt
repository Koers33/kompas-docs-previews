# Create or update a business partner relationship type

Add a relationship role to the shared catalogue or maintain an existing type’s name, description, area or active status.

## Who can do this?

The app requires portal access and has no additional entity-level role restriction in its service. Your administrator controls whether the app is assigned to your launchpad and whether you have the required access.

## What do I need before I start?

- The purpose of the relationship type and the name and description users should see.
- The **Area** the type belongs to. Existing business partner relationships inherit their type’s area when you run **Sync Area**.
- For a new type, a code and the required relationship details. The code identifies the catalogue entry.

Before deactivating a type or changing a type already used on partner records, check how that relationship is used. Types such as **Client Admin** and **Partner Manager** affect client access.

## How do I complete the task?

1. Open **Business Partner Relationship Types**. Select **Create** to add a type, or open an existing type to maintain it.
2. For a new type, enter its **Code**. Enter or update its **Name** and description, choose its **Area**, and set **Active** as needed.
3. Review the values and select **Save**.
4. If you changed the **Area** of an existing type, check **Synced**. If it is off, follow [Change a relationship type’s area and sync existing relationships](./change-a-relationship-types-area-and-sync-existing-relationships).

## How do I know it worked?

The type shows the saved name, description, area and active state. For a new type, its code appears in the catalogue. If you changed the area of an existing type, **Synced** remains off until you synchronize the relationships that use it.

## What if I can’t complete it?

- If the app is not available in your launchpad, ask your platform administrator to check your portal access and app assignment.
- If the saved type has an area change but **Synced** is off, run **Sync Area** using the separate guide linked above; saving the type alone does not update existing relationships.
- Relationship types are non-deletable master data. If a type should no longer be used, review its **Active** state rather than expecting to delete it.
