# Projects app

Projects is where client projects are recorded and kept together. A project belongs to a **Client** and a **Counter Party**, carries a **Project Code**, **Project Description**, **Project Type** and the dates it runs between, and holds the phases, requests, notes and documents that belong to it.

## What is this app for?

The list shows every project you are entitled to see, with its code, client, counter party, description, dates and type. Opening a project shows its details under **Project**, followed by the **Project Phase**, **Client Request**, **Project Notes** and **Documents** sections.

A phase is a stage of work inside the project. It has a category, a name, a status and its own dates, and opening a phase gives you its project items, its notes and its documents.

## When should I use this app?

Use it to set up a project for a client before work is tracked against it, to add or review phases, to see the requests raised against that project, and to keep the project's discussion and files in one place.

The client-specific choices a project draws on — phase categories, item types, payment groups and the rest — are maintained in [Projects Master Data](/apps/transactional/project-masters), and the individual work items belong in [Project Items](/apps/transactional/project-items).

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). No narrower launchpad audience is recorded for it, so it is treated as available to anyone with portal access.

The records behind the screen are scoped: the **Treasury** role has full use of projects, and a user holding the **Client** role gets the same use only for a client business partner they are actively linked to as a **Project Manager**. The **Project Viewer** relationship gives read-only access. Client users therefore see a narrower set of projects than treasury users do.

## How does work progress in this app?

1. Create the project: choose the client, the counter party and the project type, then give it a code, a description and its start and end dates, and save.
2. Add phases under **Project Phase**, each with its own category, name and dates. The phase carries a status you can read at a glance, and opening it opens its items, notes and documents.
3. Record the requests raised for the project under **Client Request** — they are worked in the [Requests app](/apps/transactional/requests).
4. Keep the conversation in **Project Notes** and the supporting files in **Documents**.
5. The first project you create for a client also gives that client its own risk percentage rows, copied from the platform defaults — they are listed in [Risk Project Percentages](/apps/transactional/risk-project-percentages).

The project record itself has no status workflow to drive: it is the container that the phases, items and requests move through.

## What can change what I see or do?

- **The sections appear once the project is saved.** A project you have not saved yet shows only its details; the phase, request, notes and documents sections appear after the save.
- **The value helps are scoped to the chosen client.** Only client business partners are offered as **Client**, **Counter Party** offers the active organisation relationships recorded for the client you selected, and the client-scoped lists such as phase categories are filtered the same way.
- **Saving is refused, with the value named, when** a **Project Code** already exists, when two phases in the same project share a name, when a phase would end before it starts, or when a phase's dates fall outside the project's dates.
- **Notes are not shared indiscriminately.** Treasury users see the notes flagged **Show To Treasury**, and a client user sees the notes they created themselves.
- **There is no delete command for a project.** Correct or close a project rather than expecting to remove it.
- **Your relationship decides what you can change:** a client user linked as a **Project Viewer** can read the project but not edit it.

## Where can I review the results?

The list is the quickest check: code, client, counter party, dates and type per project. Inside the project, **Project Phase** shows each phase with its status and dates, **Client Request** shows the requests raised against the project, and **Project Notes** and **Documents** hold the discussion and files.

Requests raised here are tracked in [Requests](/apps/transactional/requests), the work items in [Project Items](/apps/transactional/project-items), and the risk bands seeded for the client in [Risk Project Percentages](/apps/transactional/risk-project-percentages).

## What should I check if I can’t continue?

- **A save is refused naming the project code:** that code is already used — choose another one.
- **A save is refused naming a phase date:** phase dates must sit inside the project dates, and a phase cannot end before it starts.
- **The phase, request or notes sections are not there yet:** the project has not been saved.
- **A counter party is missing from the list:** its relationship with the client is not recorded as active — see [Business Partners](/apps/transactional/business-partners).
- **An edit control is missing:** your link to that client is read-only — see [Roles and Access](/getting-started/roles-and-access).
