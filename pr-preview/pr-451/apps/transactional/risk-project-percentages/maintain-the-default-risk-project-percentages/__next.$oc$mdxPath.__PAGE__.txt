# Adjust the default risk percentage bands

Change the platform's default percentage bands that will be copied to a client when its first project is created and it has no risk bands yet.

## Who can do this?

The **Treasury** role is required. Review the impact of a default change with the risk-policy owner before saving it.

## What do I need before I start?

- The approved default minimum, maximum and risk percentages.
- Confirmation that the change is intended for future client setups; existing client-specific bands are not updated by changing defaults.
- The current bands in the **Default Risk Percentages** view, so you can preserve complete and non-overlapping coverage as required by your policy.

## How do I complete the task?

1. Open **Risk Project Percentages** and switch to **Default Risk Percentages**.
2. Review the existing default rows. Open the band to adjust; default rows are separate from client-specific bands.
3. Update **Minimum Percentage**, **Maximum Percentage** or **Risk Percentage** as approved. Keep each value between 0 and 100.
4. Save and activate the draft. Do not delete or repurpose a default band that has a different meaning.
5. Reopen **Default Risk Percentages** and verify the saved values and active state.

## How do I know it worked?

The updated values appear in the **Default Risk Percentages** view. When a client with no existing bands has its first project created, these defaults are copied into client-specific rows.

## What if I can’t complete it?

- If the view is empty, confirm you selected **Default Risk Percentages**, not the **Active** or **Inactive** client-band view.
- If a value is outside 0–100, correct it and save again.
- Existing client bands are not retroactively changed by default edits. Update those client rows separately using [Maintain risk percentage bands for a client](./maintain-risk-project-percentages-for-a-client).
- The app does not validate whether ranges overlap or leave gaps; review the full default set before saving.

## What should I do next?
