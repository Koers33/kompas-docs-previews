# Status Lists app

Status Lists is where the platform's status picklists are maintained. Every dropdown that carries a workflow state — settlement status, approval status, deal lifecycle status, journal status and the rest — draws its options from one of these lists, so the entries you maintain here are the values users see everywhere else.

## What is this app for?

The main list shows one row per status list, identified by its **Entity Name** and grouped by **Domain Group**. Opening a row shows **General Information** and, below it, **Status List Entries**: each entry's code, name, description and whether it is active.

The app is deliberately narrow. The status list rows themselves cannot be created or deleted, and their **Entity Name** and **Domain Group** are read-only — they name an existing list. The work happens in the entries: adding a value, correcting a display name or description, or switching a value off.

## When should I use this app?

Come here to add a status value a user needs in a dropdown, to correct how a status reads, to retire a value that should no longer be offered, or to re-synchronise a list after a change made elsewhere.

Choosing a status on a deal, a payment or a journal belongs in the app where that record is worked — not here.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). The status lists carry no additional role restriction beyond that portal access, so everyone who can open the app sees the same lists.

## How does work progress in this app?

1. Filter or browse by **Domain Group** — the list opens grouped by domain and sorted by **Entity Name**.
2. Open the status list and work in **Status List Entries**. An entry needs a code and a name; saving it writes the change straight through to the live list that other apps read.
3. Use **Refresh Entries** to reload the entries from the live list, replacing what this record currently shows. Use it when the live list has changed elsewhere and your view looks out of date.
4. Use **Update Entries** to push what you see back to the live list: codes that do not exist yet are created, and existing ones are updated.

Steps 3 and 4 are the two directions of the same synchronisation, so pick the direction you need: refresh pulls, update pushes.

## What can change what I see or do?

- **Domain Group** is the only filter on the main list and the grouping used in the table.
- **The list row is fixed.** **Entity Name** and **Domain Group** are read-only, and status lists cannot be created or deleted here.
- **Entries cannot be deleted.** Switch **Is Active** off instead of removing a value, so records that already reference it stay valid.
- **An entry needs a code and a name.** Saving without one is refused with a message telling you which field is missing.
- **Refresh replaces what you see.** It reloads the entries from the live list, so the view you were editing becomes the live list's current contents.

## Where can I review the results?

Reopen the status list and check **Status List Entries**: after a save or an update it shows the code, name, description and active flag you just wrote, and after a refresh it mirrors the live list.

The real test is where the value is used. Open the app that offers the dropdown — for example the **Settlement Status** filter in the [Settlements app](/apps/transactional/settlements) — and confirm the new or corrected option is offered there, since those dropdowns read the live status list.

## What should I check if I can’t continue?

- **A message about a missing code or name:** complete the field and save the entry again.
- **An entry you expected to delete:** entries are never deleted here — deactivate the entry instead.
- **A value does not appear in a dropdown:** check the entry is active first, then check the dropdown's own app.
- **An edit control is missing:** check your roles in [Roles and Access](/getting-started/roles-and-access).
- The registered messages for this app are listed in the [block 9xx error reference](/reference/error-codes/block-9xx-csh).

## Which task guides are available?

- [Add, correct or retire a status value](./add-correct-or-retire-a-status-value)
- [Re-synchronise a status list](./re-synchronise-a-status-list)
