# Sanctions List Catalogue app

Sanctions List Catalogue is the register of the sanctions lists the platform's screening works from. Each row carries a **List Code**, a **List Name**, the **Source Authority** behind it, an **Effective Date** and an active flag.

## What is this app for?

The catalogue records which lists are in scope and in force — the authority, such as the United Nations, the European Union, OFAC, the UK Treasury, the Financial Action Task Force or the South African Reserve Bank, the name it is known by, and the date it takes effect. Rows are switched on or off rather than removed: there is no delete command for a catalogue entry.

Because a catalogue can hold many lists, the app is built for bulk work as well as single edits: a spreadsheet import stages the rows, and one action applies them to the catalogue.

## When should I use this app?

Use it when a list comes into force, when an existing list is reissued under a new name or authority, when you want to retire a list by switching it off, and when several lists have to be loaded at once from a spreadsheet.

The catalogue is configuration. The results of screening are recorded against the records that were screened — for example the screening status shown on a payment in [Payment Instructions](/apps/transactional/payment-instructions) — not here.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). No narrower launchpad audience is recorded for it, so it is treated as available to anyone with portal access.

Reading, adding and changing catalogue rows go with portal access; deleting is not offered at all.

## How does work progress in this app?

1. Filter the list to active or inactive rows and open a list to review or correct it. **List Code** is fixed once the record exists and **List Name** is required.
2. To load several lists at once, run **Import Spreadsheet** on the list page. The dialog offers **Download Template** for the expected layout, lets you choose an Excel file, and reports how many rows were staged and how many were skipped.
3. When rows are staged, **Push Now** in the same dialog applies them — or run **Update Entries** on an open record to apply whatever is staged.
4. The result reports how many rows were created and how many were updated, and lists anything it could not apply.

A row whose **List Code** already exists is updated rather than duplicated, and an import never overwrites the code itself.

## What can change what I see or do?

- **The file must be an Excel workbook** — `.xlsx`, `.xlsm` or `.xls`, and not empty. Anything else is refused by the dialog.
- **An upload replaces the previous staging.** The rows left over from an earlier upload are cleared when a new file is staged, so stage the file you intend to apply.
- **A row without a list code is skipped**, and the staging summary tells you how many rows that affected.
- **List Code is immutable.** Correct the name, authority or date instead; to use a different code you need a different record.
- **Rows cannot be deleted.** Switch the active flag off to take a list out of use.
- **The catalogue's own registry entry must exist.** If the platform's master data catalogue does not know this entity, the import and the update both fail with "The master data catalogue entry was not found" — that is an administrator's fix.

## Where can I review the results?

The list is the check: **List Code**, **List Name**, **Source Authority**, **Effective Date** and the active state per row, and the staging summary or result counts tell you what a spreadsheet actually did. Reopen a row after an import to confirm the values it carried.

Screening outcomes live with the records screened, so a screening status or a hold is read on the record it applies to, such as a payment in [Payment Instructions](/apps/transactional/payment-instructions).

## What should I check if I can’t continue?

- **"The master data catalogue entry was not found":** the platform's registry entry for this catalogue is missing — contact your administrator.
- **"Select a file first", "Invalid file type" or "File is empty":** choose a non-empty Excel workbook and upload again.
- **Nothing was staged:** check the staging summary — a missing **List Code** is the usual reason a row was skipped.
- **A push reports errors:** the rows it names could not be applied; the counts show what did land.

## Which task guides are available?

- [Correct or retire a sanctions list entry](./correct-or-retire-a-sanctions-list-entry)
- [Import sanctions lists from a spreadsheet](./import-sanctions-lists-from-a-spreadsheet)
