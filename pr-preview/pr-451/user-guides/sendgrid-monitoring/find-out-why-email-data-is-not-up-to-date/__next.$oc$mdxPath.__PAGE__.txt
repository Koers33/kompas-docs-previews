# Find out why email data is not up to date

Run a manual sync and inspect the per-data-set history to identify whether the provider refresh completed or failed.

## Who can do this?

Users with portal access can view sync history and run **Sync All**. The action refreshes data from the provider; it does not change provider records.

## What do I need before I start?

- The **Sent Emails** or other view that appears stale.
- The approximate time when the last sync should have run.

## How do I complete the task?

1. Open **SendGrid Monitoring** and review **Synced At** on a recent row.
2. Select **Sync All** to request a refresh of all monitoring data sets.
3. Open **Data Sync History** and find the latest run for the relevant data set.
4. Review **Records Synced**, start/finish times and any **Error Message**.
5. If the run succeeded, return to the relevant view and refresh it. If it failed, give the data-set name and error message to your administrator.

## How do I know it worked?

**Data Sync History** shows a successful run with a record count, and the relevant view's **Synced At** reflects the refreshed data. Only the ten most recent runs are retained for each data set.

## What if I can’t complete it?

- If no new run appears after **Sync All**, check the sync history and confirm the action completed.
- If the history contains an **Error Message**, the provider integration or that data-set request needs administrator review; repeated retries may not help until it is resolved.
- If a sync history row is older than the period you need, it may have rolled out of the ten-run history; use the row's timestamps and ask your administrator for provider logs.

## What should I do next?
