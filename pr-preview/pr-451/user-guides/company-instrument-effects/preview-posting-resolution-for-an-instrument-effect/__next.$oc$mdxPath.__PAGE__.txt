# Preview posting resolution for an instrument effect

Check whether a saved instrument-effect row’s accounting configuration resolves to a general ledger account before relying on it.

## Who can do this?

The app requires portal access and the roles assigned to your account. The service adds no further role restriction for these records; ask your administrator if the app or action is unavailable.

## What do I need before I start?

- A saved **Company Instrument Effects** row.
- **Accounting** enabled on that row. If accounting is off, the preview reports that accounting will not run for the effect.

## How do I complete the task?

1. Open **Company Instrument Effects** and select the saved row for the company, instrument, lifecycle event and acting capacity you want to check.
2. Select **Preview Posting**.
3. Review the resolution layers and the double-entry check. The preview shows the account-resolution path and uses a notional amount; it does not post a journal entry.
4. If the result reports a hard block or an unresolved account mapping, note the financial node and mapping details for follow-up.

## How do I know it worked?

The preview reports whether the accounting chain resolves and whether its simulated debit/credit check is balanced. A hard block identifies a missing or unresolved mapping; a successful preview is not itself a posted transaction.

## What if I can’t complete it?

- If the row is an unsaved draft, save it first; **Preview Posting** requires a saved record.
- If the preview says accounting will not run, check whether the row’s **Accounting** switch is off.
- If a mapping is missing, correct the related **Financial Node Account Mappings** or **Treasury Account Master** record, then run the preview again.

## What should I do next?
