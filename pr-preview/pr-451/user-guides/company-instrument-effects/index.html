Company Instrument Effects app

Company Instrument Effects holds one row for each combination of company, Instrument, Lifecycle Event and Acting Capacity that the platform processes. A row records which of the platform’s processing steps are switched on for that combination, in what order they run, and how accounting for it is coded — so it is the place you check when you need to know why a step ran, or did not run, for a lifecycle event such as capture, confirmation, settlement or maturity.

What is this app for?

Each row is a piece of configuration rather than a transaction. It names the company and instrument it belongs to, the lifecycle event it applies to (values such as Capture, Confirm, Roll, Settlement Execution and Mature) and the acting capacity (Own Book or On Behalf), then switches the processing steps on or off.

The steps are grouped on the record as Phase 1 Engines — projected cash flows, near cash position, general ledger postings, evidence capture, the Engine Execution Order, the Financial Node, the Accounting Event and the Ledger — and Phase 2 Engines, which cover items such as mark-to-market valuation, risk, liquidity, compliance, hedge accounting, cost allocation and notifications. The Audit section carries whether the row is a Mandatory Row, whether it is Active, and its Effective From date.

When should I use this app?

Use it while setting up a company’s processing rules, when a lifecycle step needs different treatment, or when you are tracing why a step did or did not run for an event. Day-to-day deal work belongs in the Deals app; this app describes what the platform does when an event occurs, it does not record the events themselves.

Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see Roles and Access. These records carry no additional role grant of their own, so everyone who can open the app sees the same rows and the same editing controls. Rows cannot be deleted; switch Active off instead of removing a row.

How does work progress in this app?

  1. Select Create to add a row, or open an existing row to change it. Each row is saved as a draft until you save it.
  2. Set the company, Instrument, Lifecycle Event and Acting Capacity that the row applies to, then set the switches in Phase 1 Engines and Phase 2 Engines.
  3. Fill in the accounting side where postings are expected: Financial Node, Accounting Event and Ledger, plus Engine Execution Order and Effective From.
  4. Save. There is no approval step: the state of the row is the set of switches themselves.
  5. Select Preview Posting on a saved row to see how the accounting chain for that row would resolve before you rely on it.

What can change what I see or do?

  • Lifecycle event and acting capacity: a different combination is a different row. Filter the list on these to find the row that will apply to an event.
  • Active: the list marks Active green when the row is on and red when it is off, and only an active row is in effect.
  • Accounting: when Accounting is off, Preview Posting reports that accounting will not run for that row instead of resolving a posting chain.
  • Value lists: Lifecycle Event, Acting Capacity, Ledger, Accounting Event and Financial Node are chosen from fixed lists, so the options are the ones your configuration offers.
  • Deleting: rows cannot be deleted from this app. Turn Active off to retire one.

Where can I review the results?

Start with the list: its status columns show, per row, whether projected cash flows, near cash position, accounting, actual settlement and evidence capture are on, so you can scan the matrix without opening each record. On the record, Phase 1 Engines, Phase 2 Engines and Audit show the same settings in full.

Preview Posting is the check before you trust a row: it walks the resolution chain — global financial node, company financial node, account mapping, treasury account and ledger account — reports whether the posting resolves or is blocked, and says why when a mapping is missing.

Where a step actually runs, its results appear in the app that owns them — accounting entries and projected cashflows for a deal, for example, are reviewed on the deal itself in the Deals app. Do not assume every row produces every kind of record: that depends on the switches, the company configuration and how far processing has progressed.

What should I check if I can’t continue?

  • Preview Posting tells you accounting will not run: the row’s Accounting switch is off — switch it on and save if that is not what you intended.
  • Preview Posting reports a hard block or a missing mapping: the account mapping for that node is not in place; the mapping records live in Financial Node Account Mappings and Treasury Account Master.
  • Preview Posting returns nothing: run it on a saved row — an unsaved draft has no record to preview.
  • A delete command is refused: effect rows are retained by design.
  • An edit control is missing: check your roles in Roles and Access.

What should I do next?

Make sure the company and its financial nodes exist first — see the Companies app and Company Standard Financial Nodes — then review how the configured steps show up on a deal in the Deals app.
