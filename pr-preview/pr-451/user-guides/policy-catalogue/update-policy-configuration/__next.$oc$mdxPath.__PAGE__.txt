# Update policy configuration from a catalogue

Edit a policy register's staged rows and explicitly push them to the configuration the platform uses.

## Who can do this?

The app requires portal access and grants reading and writing these records on the same basis. Follow your policy or SoD change-approval process before pushing shared configuration.

## What do I need before I start?

- The register to change and the approved replacement values.
- The required code and name for each row; a row's code is fixed after it has been set.
- Confirmation that the register is writable here. Policy-violation and SoD-violation logs are read-only.

## How do I complete the task?

1. Open **Policy Catalogue** and select the relevant register.
2. Run **Refresh Entries** before editing. This replaces the staged rows with the register's current configuration, so it also discards earlier staged edits for that register.
3. In **Catalogue Entries**, add or edit the required rows. Complete **Name** and any required **Code**; switch off an existing row that should no longer be used rather than deleting it.
4. Save the staged rows. Saving alone does not change the live policy configuration.
5. Review the staged values, then run **Update Entries** to apply them.
6. Refresh the register and confirm the intended rows and values are present.

## How do I know it worked?

After **Update Entries**, a fresh **Refresh Entries** loads the live configuration. Confirm the changed values appear and inactive entries remain retained.

## What if I can’t complete it?

- If refresh removed your work, the staged copy was replaced. Re-enter the approved edits after refreshing.
- If **Update Entries** names a missing name, duplicate code, changed code or invalid inactive-on-create row, correct the staged values and push again.
- If the register is a read-only violation log, there is no write action for it.
- If no staging rows exist, run **Refresh Entries** to load the current register before editing.

## What should I do next?
