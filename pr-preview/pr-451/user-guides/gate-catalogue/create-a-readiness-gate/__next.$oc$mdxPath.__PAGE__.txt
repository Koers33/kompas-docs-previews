# Create a readiness gate in development

Add a readiness-gate definition in a development environment for a reviewed platform setup change; production gate definitions arrive with platform setup and cannot be created here.

## Who can do this?

The app requires portal access and the roles assigned by your administrator. Gate creation is restricted to development; the service refuses it in production. Use your platform setup and release process before adding a shared gate definition.

## What do I need before I start?

- Approval for the new shared gate definition and its intended business meaning.
- A unique code using the prefix for its series—**SG** (Setup), **IG** (Instrument), **OG** (Operational), **RG** (Readiness) or **CG** (Conditional)—followed by two digits.
- The gate name, type, business domain, accountable active owner role, enforcement method, basis and legal-review status.
- A change reason of at least 10 characters. The reason is required for gate creation and is written to **Mapping History**.
- The gate's checks prepared through the platform setup process. Checks cannot be created from this app.

## How do I complete the task?

1. Confirm the system is running in **development** and open **Gate Catalogue**.
2. Select **Create** and enter the **Readiness Gate Code**, **Name** and **Readiness Gate Series**. The code prefix must match the selected series and the code must be unique.
3. Complete the gate type, business domain, accountable owner role, enforcement, basis and required setup details. Enter the change reason.
4. Save the draft and activate it through the app's normal draft-save flow. The platform assigns the sequence; a new gate starts inactive.
5. Reopen the record and check **Mapping History** for its creation entry. Coordinate with the platform setup owner to ensure its checks are supplied before anyone activates it.

## How do I know it worked?

The new gate appears with its assigned sequence and is inactive. **Mapping History** contains a **CREATED** entry with the gate code and reason.

## What if I can’t complete it?

- If creation is refused outside development, do not retry in production; include the gate in the approved platform setup/release instead.
- If the code is rejected, use two letters and two digits, with the correct series prefix, and check that it is not already in use.
- If the reason is missing or shorter than 10 characters, enter a clear reason of at least 10 characters.
- If the owner role is inactive, select an active accountable role.
- A new gate cannot be activated until it has at least one check. Check rows are maintained through platform setup, not this app.

## What should I do next?
