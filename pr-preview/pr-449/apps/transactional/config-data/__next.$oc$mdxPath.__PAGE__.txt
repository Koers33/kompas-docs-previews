# Config Data app

Config Data is the catalog of a company's governed configuration registers. Each register row names one area of configuration the platform treats as controlled — a **Register Code** and **Register Name**, a short description, the **Register Category** it belongs to, the **Approval Level** changes to it require, how many days pass between reviews (**Review Cycle (Days)**), and whether the register is currently **Is Active**. The catalog is the index: it says which configuration areas exist and how they are governed, not the values inside them.

## What is this app for?

The catalog exists so configuration governance has one visible home. The **Register Category** places a register in a business area — categories include **Hedge Accounting**, **Regulatory**, **Accounting**, **Security**, **Platform**, **Data Governance**, **Workflow** and **Notification** — and the **Approval Level** records how much sign-off a change to that area needs, from **Treasury Manager Required** through **Dual Approval** and **Compliance Required** up to **Board Required**. **Review Cycle (Days)** states how often the register should be revisited; it starts at 365 days.

## When should I use this app?

Use it when a new area of configuration needs to be registered, when the approval level or review cycle for an existing area changes, or when you need to confirm which registers a company treats as governed and which are still active. This app maintains the registers themselves — the day-to-day activity each register describes belongs in the apps for that work.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). At the service level, reading, creating and updating these records is granted to portal access, with no further role restriction, so everyone who can open the app sees the same catalog and the same editing controls. Registers cannot be deleted: switch **Is Active** off to retire one.

## How does work progress in this app?

1. Open a register to review or correct it, or select **Create** to register a new configuration area.
2. Complete the mandatory fields — **Register Code**, **Register Name**, **Register Category** and **Approval Level**. The app marks them mandatory and refuses a save that leaves one blank.
3. Add the description, set **Review Cycle (Days)** and leave **Is Active** on while the register is in use.
4. Save. The register code has to be unique for the company, so a second register cannot reuse one that already exists.
5. When an area is no longer governed as a register, switch **Is Active** off rather than deleting it.

There is no approval step inside this app: the **Approval Level** recorded on the register describes what approval the governed area requires elsewhere.

## What can change what I see or do?

- **Register Category** and **Approval Level:** both are chosen from fixed lists, so only the categories and approval levels your configuration offers can be selected.
- **Is Active:** it filters the list and tells you whether a register is currently in use; retired registers stay on file.
- **Review Cycle (Days):** the interval the register is reviewed on; it is stored on the register and shown in the list and on the record.
- **Deleting:** registers cannot be deleted from this app.
- **A blank or duplicate field:** saving checks the mandatory fields and the uniqueness of the register code, and the message names what to fix.

## Where can I review the results?

The list carries the catalog itself: **Register Code**, **Register Name**, **Register Category**, **Approval Level**, **Review Cycle (Days)** and **Is Active** for every register, filterable by category, approval level and active state. The record shows the same fields plus the description, so you can confirm what a register covers and how it is governed without opening anything else.

Because the catalog is an index rather than a transaction list, the proof that a register is correct is the catalog itself — there is no downstream record this app produces.

## What should I check if I can't continue?

- A save is refused with a blank-field message: **Register Code**, **Register Name**, **Register Category** and **Approval Level** are all mandatory.
- You are told the register code already exists: choose a different code — codes are unique per company.
- A delete command is refused: registers are retained by design.
- The registered messages for this app are listed in the [block 19xx error reference](/reference/error-codes/block-19xx-cfg).
- An edit control is missing: check your roles in [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

No task guide is published for this app yet; creating a register, correcting one and retiring it are covered on this page.
