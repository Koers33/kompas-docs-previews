# Policy Catalogue app

Policy Catalogue is where the platform's policy configuration is maintained in one place. The list holds one row per register — the policy rules a company works to, the parameters and exceptions set against them, the segregation-of-duties rules and their exceptions, and the two registers that record policy and segregation-of-duties violations. Each row is identified by its **Entity Name** and grouped by **Domain Group**, and every register in this app belongs to the policy domain group. Opening a register shows its rows in the **Catalogue Entries** section.

## What is this app for?

The app works in two steps: you edit a working copy of a register's rows in **Catalogue Entries**, then push those rows to the configuration the platform actually uses. Saving an edit on its own changes only the working copy — **Update Entries** is what makes an edit part of the configuration.

The two violation registers are different in kind: they carry recorded violations rather than settings, so they are read-only in this app.

## When should I use this app?

Use it when a policy rule, a company parameter or exception, or a segregation-of-duties rule or exception has to change, and when you want to see exactly what is configured before a review or a discussion about how the platform behaves.

Picklist values behind the platform's dropdowns are maintained separately from these policy records. The platform's record of what each entity holds is in the [Master Data Catalogue app](/apps/transactional/master-data-catalogue). Neither is maintained here.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). No narrower launchpad audience is recorded for it, so it is treated as available to anyone with portal access. The service behind the screen grants reading and writing these records on the same basis and sets no additional role gate of its own.

## How does work progress in this app?

1. Open a register from the list, narrowing by **Domain Group** first if you want.
2. Run **Refresh Entries**. It loads the register's current rows into **Catalogue Entries** and replaces any rows you had staged for that register.
3. Add or edit rows in **Catalogue Entries**. **Name** is required; where the register uses a code, enter it once, because it cannot be changed after it has been set; a row cannot be created already switched off.
4. Save. Saving keeps the rows staged — the configuration is still untouched.
5. Run **Update Entries**. Every staged row is validated first and only then written, so one bad row stops the push rather than leaving the register half-updated.
6. For a bulk change, use **Import Spreadsheet** on the list: choose the register, **Download Template** for the layout, **Upload** your file, read the staged and skipped counts, then **Push Now**.

## What can change what I see or do?

- **Refresh replaces staged rows.** Run it before you start editing, not after — rows staged earlier for that register are discarded when it runs.
- **Validation decides whether a push lands.** A duplicate code, a missing name, a code you tried to change, or a row created switched off is refused, and nothing is written until it is corrected.
- **Some registers are read-only.** **Update Entries** is refused outright for the two violation registers, and the import dialog does not offer every register either.
- **Nothing is deleted here.** Neither a register nor its rows has a delete command; a row you no longer want is switched off instead.
- **A saved row is not yet live.** Rows you saved but did not push exist only in the staged copy.

## Where can I review the results?

Reopen the register and read **Catalogue Entries** — it shows the rows as they now stand. To be sure you are looking at live values, run **Refresh Entries** again: it reloads straight from the configuration, so anything that did not take effect is missing from the list. The list itself gives the wider view across registers, with **Entity Name** and **Domain Group** per row.

## What should I check if I can’t continue?

- **Update Entries refuses a row:** the message names the register and the code — a duplicate, a missing name, a code you tried to change, or a row created switched off. Correct the staged row and push again.
- **Update Entries refuses the register:** that register is read-only in this app, so there is nothing to push.
- **Update Entries appears to do nothing:** there are no staged rows for the register — run **Refresh Entries** first.
- **A register is missing from the import dialog:** only the registers the import supports are offered there.
- **A permission message:** your roles do not cover the record — see [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

No task guide is published for this app yet; refreshing, editing, pushing and importing are covered on this page. Read [Using the Fiori Apps](/getting-started/using-fiori-apps) once for how drafts, value helps and save behaviour work across the platform.
