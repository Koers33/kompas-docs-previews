# Financial Node Account Mappings app

Financial Node Account Mappings decides which general ledger account each of a company's financial nodes posts to. One row ties a company, a financial node, an **Accounting Path** and a **Leg Role** to a **Treasury Account** and a **General Ledger Account**, and its **Mapping Status** says how much that pairing can be relied on right now.

## What is this app for?

Each mapping answers one posting question: when work happens on this node, along this path and in this role, which account is used? The **Accounting Path** values are **Own Book**, **Client**, **All** and **Hybrid**, and the **Leg Role** values describe the account's job — position, income, expense, other comprehensive income reserve, settlement, fund transfer pricing charge or credit, expected credit loss allowance, and suspense.

The **Mapping Status** values read as follows: **Unlinked** (the node has no active account mapping), **Linked** (the node is actively mapped to an account), **Review Required** (the mapping needs review before it can be relied upon), **Pending Approval** (proposed but not yet approved), **Superseded** (replaced by a newer mapping record) and **Dormant** (the mapping exists but is not currently in use).

## When should I use this app?

Use it when setting up a company's accounting, when a node's account changes, or when you need to check why a node posts where it does. Run it before go-live to confirm every active node is covered. It is also the place to answer a "which account is this node using" question during review.

Client-specific overrides are not done here — they belong in the [Client GL Overlays app](/apps/transactional/client-gl-overlays), and the nodes themselves are maintained in the [Company Standard Financial Nodes app](/apps/transactional/company-standard-financial-nodes).

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). The register applies no role restriction of its own beyond portal access, but one action checks your role directly: **Approve GL Mapping** is refused unless you hold the **Treasury** role. Treat approval as a governed step and follow your approval procedure before using it.

## How does work progress in this app?

1. Create a mapping in draft: choose the company, the **Company Financial Node**, the **Accounting Path** and the **Leg Role**, then select the **Treasury Account** and **General Ledger Account**. Only one active mapping is allowed per node.
2. Select **Validate All Mappings** on a saved mapping. It checks the company's active nodes against its active mappings, reports the nodes that have none, and tells you whether you are ready for go-live — either "ready, nothing missing" or "n missing mappings, resolve before go-live".
3. When a node's definition changes afterwards, its linked mappings are flagged **Review Required**. Open the record and select **Review GL Mapping**: confirming the mapping returns it to **Linked**; not confirming clears the account and leaves it **Unlinked**.
4. For balance-sheet accounts, select **Request CFO Approval** to raise the approval request and move the mapping to **Pending Approval**. A Treasury user then selects **Approve GL Mapping**, which records the approval and returns the mapping to **Linked**.
5. Changing the account on an existing mapping does not overwrite history: the previous mapping becomes **Superseded** with an end date, and a new **Linked** mapping takes its place from that day.

## What can change what I see or do?

- **Action availability:** **Review GL Mapping** is offered only for a saved mapping in **Review Required**; **Request CFO Approval** only for a saved mapping whose account type is a balance-sheet type; **Approve GL Mapping** only while the mapping is in **Pending Approval**; **Validate All Mappings** only for saved records.
- **Account compatibility:** a general ledger account whose type does not suit the node's category is refused when you save, as is an account that is switched off or unknown. The value help for **General Ledger Account** is already narrowed to the account type on the mapping.
- **One mapping per node:** a second active mapping for the same node is refused — open the mapping that already exists.
- **Duplicate account:** if the account you pick is already mapped to another node of the same company, the save succeeds with a warning rather than being blocked.
- **Status set by the platform:** deactivating an instrument moves the affected mappings to **Dormant**, and changing a node flags its linked mappings as **Review Required**.
- **No deletion:** mappings cannot be deleted from this app; use the status and the account fields instead.

## Where can I review the results?

The list shows each mapping's company, node, path, leg role, accounts, **Mapping Status** and **Active** flag at a glance. On the record, **Mapping Definition** holds the pairing itself with its effective dates, **Approved By**, **Approval Reference** and remarks, while **Chain Preview** walks the same mapping end to end — global node, company node, accounting path and leg role, treasury account, then the GL code, account name and IAS 7 class.

## What should I check if I can't continue?

- An approval is refused: only balance-sheet account types can be sent for approval, and approval needs the **Treasury** role.
- **Review GL Mapping** is not offered: the mapping is not in **Review Required**.
- Saving is refused with a category or duplicate message: choose a general ledger account whose type suits the node. The registered messages are listed in the [block 5xx error reference](/reference/error-codes/block-5xx-res) and the [block 6xx error reference](/reference/error-codes/block-6xx-acc).
- A node already has an active mapping: open that record rather than creating another.
- The app itself does not open: check your access first — see [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

No task guide is published for this app yet; creating a mapping, validating coverage, reviewing it and completing an approval are covered on this page.
