# Master Data Catalogue app

Master Data Catalogue is the platform's map of its own data. Each row is one entity: it shows whether the entity is master data, its data category and the **Domain Group** it belongs to, and it carries a **Context Card** that records what the entity is for and how it is governed.

## What is this app for?

The row itself holds the facts the platform maintains — **Entity Name**, the **Master Data** flag, **Domain Group** and **Entity Type**. The **Context Card** holds the context you add: a purpose summary, the kind of entity it is (Master Data, Transactional, Code List, Immutable Ledger or Runtime State), the **Data Steward Role**, governance rules, related entities, its **Seed Data Status** (Seeded or Unseeded), its **Lifecycle Policy** (Soft Delete, None or 20 Year Retention), key fields, whether it is tenant-specific, the phase it was created in, its specification reference, and a glossary of the status fields it uses.

Registry rows are not yours to create or remove: they come from the platform, and the registry columns stay read-only while the card fields are what you maintain.

## When should I use this app?

Come here when you need to know what an entity holds before you rely on it — before you link other records to it, or before you explain a screen to a colleague. It is also where you record or correct the governance context for an entity, and where you blank out a **Context Card** that was filled in with the wrong detail.

Maintaining the values inside a live list belongs to the platform configuration that owns that list, not in this catalogue.

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). The catalogue records no additional role restriction and no narrower launchpad audience, so everyone who can open it sees the same entries.

## How does work progress in this app?

1. Filter by **Domain Group** and browse. The list opens grouped by the master-data flag and the domain group, sorted by entity name.
2. Open an entry and complete its **Context Card** — purpose, steward, governance rules, related entities, seed and lifecycle state, key fields and the status glossary.
3. Save. Only the card fields change; the registry columns stay as the platform set them.
4. To start over, use **Clear Card**. It empties every card field on the record and leaves the entry, its name and its registry data untouched, whether you run it on a saved record or on a draft.

## What can change what I see or do?

- **Entity Type**, **Seed Data Status**, **Lifecycle Policy** and **Data Steward Role** are chosen from fixed platform lists, so only those values are offered.
- **Related Entities** must name entities that already exist in the catalogue. A name that is not there is refused when you save: "Related entity … is not in the master data catalogue" — see the [33xx error reference](/reference/error-codes/block-33xx-apc).
- There is no create or delete command for registry entries, so nothing here can remove an entry. **Clear Card** is the reset that is available.
- The list page also offers read-only views of live lists such as account groups, status lists and non-trading dates, so you can inspect a list without leaving the app. Those views are read-only; the app that owns the list is where its values are maintained.

## Where can I review the results?

Reopen the entry: **General Information** shows the entity name and the master-data flag, and the **Context Card** shows what you just saved. The list itself gives the domain-wide view, with **Entity Name**, **Master Data**, **Domain Group** and **Entity Type** per row. The read-only list views on the same page show the live values the catalogue points at.

## What should I check if I can't continue?

- A save is refused because a related entity is unknown: correct the name so it matches an entry in this catalogue — see the [33xx error reference](/reference/error-codes/block-33xx-apc).
- No create or delete command appears: registry entries belong to the platform. Use **Clear Card** instead of deleting.
- An edit control is missing: check your roles in [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

No task guide is published for this app yet; browsing the catalogue, filling in a card and clearing one are covered on this page. Read [Using the Fiori Apps](/getting-started/using-fiori-apps) once for how drafts, value helps and save behaviour work across the platform.
