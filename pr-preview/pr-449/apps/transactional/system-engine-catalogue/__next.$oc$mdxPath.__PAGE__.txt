# System Engine Catalogue app

System Engine Catalogue is the register of the platform's processing engines. Each row is one engine, identified by its **Engine Code** and **Engine Name**, classified by **Engine Group**, **Sprint Introduced** and **Implementation Status**, and carrying a plain-language **Purpose Summary** that says what the engine is for.

## What is this app for?

An engine is the component that does the platform's work when something happens — the logic behind a calculation, a check or a posting. The catalogue exists so that this can be read rather than guessed: each record states what the engine does, where it shows up (the apps, buttons and scheduled jobs that trigger it), what it depends on and what blocks it, plus any parameters it governs.

The record is also the place to record status and intent: an engine that has been designed but not started, one under construction, one running in production, or one that has been retired.

## When should I use this app?

Use it to find out what an engine does before you rely on an explanation of platform behaviour, to record an engine that is being added, to update a purpose, dependency or status as work progresses, and to see which engines are actually live.

Day-to-day deal and accounting work stays in the apps where those records are worked. To see the platform's pipeline runs rather than the engines behind them, use the [Pipeline Orchestration app](/apps/transactional/pipeline-orchestration).

## Who can access this app?

The app is reached through portal access plus the roles your administrator has assigned you — see [Roles and Access](/getting-started/roles-and-access). The catalogue's own grants only restate that portal access, and no narrower launchpad audience is recorded, so everyone who can open the app sees the same engines.

## How does work progress in this app?

1. Filter by **Engine Group**, **Implementation Status** or **Sprint Introduced** to narrow the list.
2. Open an engine and complete **General**: its code, name, group, sprint, pipeline and effect domain, its implementation status, and the purpose it serves.
3. Record where it appears — the apps, buttons and scheduled jobs that trigger it.
4. Record **Dependencies**: what it depends on, what blocks it, any parameters it governs, and where its specification and source live.
5. Save. An engine cannot be saved without an **Engine Code**, an **Engine Name**, a **Purpose Summary** and an **Implementation Status**.

The app offers no action buttons: engines are added and edited through the record itself.

## What can change what I see or do?

- **Filters** are **Engine Group**, **Implementation Status** and **Sprint Introduced**.
- **Implementation Status** is the record's state: **Planned** (not yet started), **In Progress** (being developed), **Implemented** (deployed and operational), **Deprecated** (retired but retained) or **Deactivated** (disabled).
- **Engines are never deleted.** Retiring one means moving its status to **Deprecated** or **Deactivated**, which keeps the row and its history.
- **The classification values are fixed.** Engine group, sprint, effect domain and implementation status come from lists the app only reads, so only those values are offered — a value you expect but cannot find has not been added to that list.
- **Four fields are mandatory:** engine code, engine name, purpose summary and implementation status.

## Where can I review the results?

Reopen the record and check **General** and **Dependencies** against what you intended to record. The list itself shows each engine's code, name, group, sprint and status per row, so filtering it by **Implementation Status** is the quickest way to see what exists and how far it has got.

## What should I check if I can't continue?

- **A save is refused because a field is empty:** complete the engine code, name, purpose summary or implementation status and save again.
- **A group, sprint, effect-domain or status value is missing:** those lists are read-only in this app and hold only the values shipped with the platform.
- **An edit control is missing:** check your roles in [Roles and Access](/getting-started/roles-and-access).

## Which task guides are available?

No task guide is published for this app yet; finding an engine, updating one and reading its dependencies are covered on this page. Read [Using the Fiori Apps](/getting-started/using-fiori-apps) once for how drafts, value helps and save behaviour work across the platform.
