# User Management Testing Guide

This guide walks you through testing the **IAS User Management** app on the live BTP
Cloud Foundry deployment.

---

## FLOW 1 — Onboard a User (Treasury: IAS User Management)

**App**: User Management (Work Zone tile)  
**Role needed**: Treasury  
**Under test**: `refreshData`, `claimUser`, `onboardClient`, `revokeAccess`

### Step 1.1 — Open the IAS User Management App

From the **SAP Build Work Zone launchpad**, locate and click the **IAS User Management**
tile. This opens a List Report displaying all users synced from SAP IAS.

**What you should see:**
- Columns: First Name, Last Name, Email,  Groups Count, Has Partner
- Colour-coded criticality: green = good, orange = warning, red = needs attention

### Step 1.2 — Refresh IAS Data

If users are missing or you need the latest data:

1. Click the **Refresh Data** button in the toolbar
2. This calls the `refreshData()` action on the service, which:
   - Calls `GET /Users` on the IAS SCIM API via the `cua-ias` destination
   - Upserts every IAS user into the local `Users` table
   - Also syncs group membership data

> **BTP note**: If this fails, the `cua-ias` destination may not be configured or the
> IAS tenant trust may not be established. Check `cf logs kompas-srv --recent` for errors.

### Step 1.3 — Select a User to Claim

In the List Report, find a user who has:
- **Has Partner** = No (red indicator — no BusinessPartner linked yet)
- **Group Count** = 0 (users that need onboarding)

### Step 1.4 — Claim the User

On the List Report Page, click the **Claim User** button.

**What happens (backend):**
1. Checks if a `BusinessPartner` already exists with `ID = iasUserId`
2. If NOT found, auto-creates a Natural Person BusinessPartner:
   - `ID` = `iasUserId`
   - `firstName`, `lastName` from the IAS user record
   - `businessPartnerCategory_code` = `"02"` (Natural Person — yes, 02 is Natural Person in this system)
   - `hasExistingEntry` = `true`
3. Auto-creates an `Email` composition record on the new BP (type `"01"`)
4. Sets `Users.hasPartner` = `true`
5. Writes everything to PostgreSQL

**Verify immediately on screen:**
- The **Has Partner** indicator turns green (value = true, criticality = 3)
- The List Report Page refreshes to show the updated status

**Verify independently:**
- Open the **Business Partners** app
- Search for the user's first or last name
- The Natural Person BP should appear with matching name and email

### Step 1.5 — Onboard as Client

The **Onboard Client** button is available on the **"Pending Onboarding"** table view in
the List Report — this view already filters to show only users who need onboarding.

Click the **Onboard Client** button on the user's row.

**What happens:**
- Assigns the `"Kompas Client"` group to the user in SAP IAS via SCIM API
- Also updates the local `UserGroups` table
- This group maps to the `Client` scope in XSUAA, granting the user client-level access

**Verify:**
- The user's **Groups Count** increases to ≥ 1 (green indicator)
- `hasPartner` turns green (onboard also claims the user, creating the BP if it doesn't exist)
- The user now has the Client role — log in to Work Zone as that user in a private
  browser window; they should see only client-accessible tiles

### Step 1.6 — Revoke Access (Test Undo)

Open the user's **Object Page** and click the **Revoke Access** button in the header.

**What happens:**
- Calls IAS SCIM API to remove ALL group assignments from this user
- Does NOT delete the BusinessPartner record — the BP remains in the database
- The user immediately loses all role-based access (XSUAA token refresh required)

**Verify:**
- **Groups Count** drops to 0 (red indicator)
- The BusinessPartner record still exists — open Business Partners app and search for the user's name to confirm

> **Important**: After revoke, it may take a few minutes for the XSUAA token to expire.
> The user might retain cached access until their next token refresh.

## Troubleshooting

| Issue                                              | What to Check                                                                                  |
|----------------------------------------------------|------------------------------------------------------------------------------------------------|
| No users appear                                    | `cua-ias` destination configured in BTP Destination Service? IAS trust established? Check `cf logs kompas-srv --recent` for SCIM API errors |
| Refresh Data fails with error                      | IAS SCIM API credentials in `cua-ias` destination may be expired. Check destination configuration |
| Claim User says "BusinessPartner already exists"   | User was previously claimed. Check `hasPartner` flag — if true, the BP already exists |
| Onboard Client fails                               | IAS group "Kompas Client" must exist in the IAS tenant. Check `cf logs kompas-srv --recent` |
| Revoke Access does not immediately block user      | XSUAA tokens are cached (typically 30 min). User retains access until token expiry |
| 403 Forbidden on any action                        | Your user does not have the required XSUAA role. Check role collection assignments in BTP cockpit → Security → Role Collections |
| 500 Internal Server Error                          | Check backend logs: `cf logs kompas-srv --recent`.
